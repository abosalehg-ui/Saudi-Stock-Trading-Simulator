# دراسة التصميم والألوان وقابلية الاستخدام على الجوال

**المشروع:** تداول — محاكاة سوق الأسهم السعودي (v3.1.0)
**نطاق الدراسة:** الهوية البصرية، نظام الألوان، التخطيط (Layout)، تجربة الجوال، إمكانية الوصول
**المنهجية:** فحص آلي عبر Chromium (Playwright) على ثلاث مقاسات (360×740، 390×844، 1440×900)، قراءة الأنماط المحسوبة (computed styles) من المتصفح فعلياً، حساب نِسَب التباين (WCAG 2.1) رياضياً، ومراجعة `src/styles/main.css` (1083 سطراً) و`index.html`.

> كل رقم في هذا التقرير مقيس من المتصفح مباشرة، وليس تقديراً بصرياً.

## 1. الملخص التنفيذي

التطبيق **وظيفياً غني جداً** (91 سهماً، مؤشرات فنية، سيناريوهات، مسارات تعلم)، لكن الطبقة البصرية لم تواكب هذا النمو. المشكلة ليست «ذوقاً» فحسب — هناك **أخطاء CSS حقيقية** تكسر التخطيط على الجوال، وليست مجرد خيارات لونية.

أهم ثلاث نتائج:

| # | النتيجة | الأثر |
|---|---------|-------|
| 1 | **الرسم البياني عرضه 56px فقط على شاشة 360px** — قاعدة CSS مكرّرة تلغي إعداد الجوال | ميزة أساسية (الشارت) غير قابلة للاستخدام على الجوال إطلاقاً |
| 2 | **30.5% من ارتفاع شاشة الجوال محجوز دائماً** لشريطين متحركين + شريط إحصائيات لاصق، مع **فجوة 32px** يظهر المحتوى من خلالها | مساحة القراءة الفعلية أقل من 70%، ومظهر «مكسور» عند التمرير |
| 3 | **23 لوناً مكتوباً يدوياً** و123 استخداماً مباشراً مقابل 21 استخداماً فقط لمتغيرات `var()` | لا يوجد نظام ألوان فعلي — التعديل اللوني اليوم يتطلب تعديل عشرات الأسطر |

## 2. أخطاء مؤكَّدة (Bugs) — أولوية قصوى

هذه ليست اقتراحات ذوقية، بل سلوك مكسور تم إثباته بالقياس.

### 2.1 قاعدة مكرّرة تُلغي تخطيط الجوال للنافذة المنبثقة 🔴

```css
/* السطر 709 — داخل @media (max-width: 768px) */
.portfolio-details, .order-details, .stock-details-grid { grid-template-columns: 1fr; }

/* السطر 767 — خارج الـ media query، وبعدها في الملف → يفوز */
.stock-details-grid { display: grid; grid-template-columns: 1fr 1fr; gap: 20px; }
```

القاعدة الثانية تأتي لاحقاً بنفس درجة التخصيص (specificity)، فتفوز حتى داخل شاشة الجوال.

**القياس الفعلي على 360px:**
```
grid-template-columns = "221.672px 56.3281px"
عرض .chart-container = 56px
```

النتيجة: الشارت يُضغط في عمود بعرض 56 بكسل بارتفاع 300 بكسل — شريط عمودي غير مقروء. وخانات اختيار المؤشرات (SMA 20 / SMA 50) تنكسر على سطرين.

**الإصلاح:** نقل قاعدة السطر 767 إلى ما قبل الـ media query، أو تحويلها إلى `grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))` لتتكيّف تلقائياً دون الحاجة لنقطة توقف أصلاً.

> يوجد أيضاً تعريف مكرر لـ `.order-form` (السطران 519 و777) — يجب دمجهما.

### 2.2 فجوة 32px في الرأس اللاصق (Sticky) 🔴

| العنصر | الارتفاع المقيس | الموضع |
|--------|------------------|---------|
| `.ticker` | 36px | `top: 0` |
| `.news-ticker` | 36px | `top: 36px` |
| `.stats` (جوال) | 122px | `top: 104px` ← **يجب أن تكون 72px** |

الشريطان ينتهيان عند 72px، لكن شريط الإحصائيات يلتصق عند 104px. الفجوة بينهما (32px) نافذة يمرّ المحتوى من خلفها أثناء التمرير — وهو ما يظهر بوضوح في لقطة الشاشة بعد التمرير (زر «جولة تعريفية» يطلّ من الفجوة).

**السبب الجذري:** الأرقام مكتوبة يدوياً (magic numbers) ولا تتبع أي مصدر واحد. **الإصلاح:** متغيرات CSS مترابطة:
```css
:root { --ticker-h: 36px; --news-h: 36px; }
.news-ticker { top: var(--ticker-h); }
.stats        { top: calc(var(--ticker-h) + var(--news-h)); }
```

### 2.3 زر اللغة يطفو فوق الشريطين 🟠

`.lang-switch` بموضع `fixed; top: 20px` وارتفاع 45px، بينما الشريطان يشغلان 0→72px.
**القياس:** تداخل مع `.ticker` = `true`، ومع `.news-ticker` = `true`.

يظهر الزر الدائري الرمادي «E» فوق أسعار الأسهم المتحركة في كل اللقطات. مكانه الصحيح داخل رأس تطبيق حقيقي (انظر §4.1).

### 2.4 أهداف لمس أصغر من الحد الأدنى 🟠

| العنصر | المقاس الفعلي | المطلوب (WCAG 2.5.5 / إرشادات Apple & Google) |
|--------|----------------|-----------------------------------------------|
| `#sharia-filter` (checkbox) | **13×13px** | 44×44px |
| `#allow-24-7` (checkbox) | **13×13px** | 44×44px |
| الـ `<label>` المحيط | ارتفاع 15px | 44px |

خانات الاختيار الأصلية غير مُنسّقة إطلاقاً. الأزرار العادية (`.btn`) تحترم `min-height: 44px` — لكن هذين الخيارين المهمين (فلتر الأسهم الشرعية، ووضع 24/7) هما الأصغر في الصفحة.

**الإصلاح المقترح:** تحويلهما إلى مفتاحين (toggle switches) أو «شرائح» (chips) قابلة للنقر بكامل مساحتها.

محسوبة رياضياً على الخلفية الفعلية لكل عنصر:

الملاحظات داخل الملف تُظهر أن التباين عولج سابقاً للأزرار وحالة السوق — لكن **التبويب النشط والتحذير الأحمر فاتا الفحص**، وهما بالذات أهم عنصرَي حالة في الواجهة.

### 2.6 أنماط ميتة (Dead CSS)

```
.header       → 0 عنصر في الصفحة
.main-content → 0 عنصر في الصفحة
```

`.header` (مع `h1` وعنوان بحجم 2em) و`.main-content` (شبكة عمودين للديسكتوب) معرّفتان في CSS لكن لا وجود لهما في `index.html`. أي أن التطبيق:
- **بلا عنوان أو هوية ظاهرة على الصفحة إطلاقاً** — لا شعار، لا اسم، لا شريط علوي
- **بلا تخطيط عمودين على الديسكتوب** — كل شيء عمود واحد ممتد

## 3. الألوان — التحليل والنظام المقترح

### 3.1 تشخيص الحالة الراهنة

**المشكلة الأولى: لوحة مشتّتة بلا نظام.** 23 لوناً hex مكتوباً يدوياً، وسبعة منها ألوان «إبراز» متنافسة:

| اللون | الاستخدام الحالي | التكرار |
|------|-------------------|---------|
| `#16a085` تركوازي | حدود + عناوين + تبويب نشط + شريط تقدم + شريط التمرير + تركيز | **25×** |
| `#1abc9c` تركوازي فاتح | عناوين ثانوية | 10× |
| `#9b59b6` بنفسجي | السيناريوهات + حد الشريط العلوي | 5× |
| `#f1c40f` أصفر | تاريخ هجري + تركيز + تمييز | 5× |
| `#f39c12` برتقالي | التحديات + الأوامر | 2× |
| `#2ecc71` أخضر | ربح | 3× |
| `#e74c3c` أحمر | خسارة | 8× |

هذه لوحة **Flat UI 2013**، وهي دلالة زمنية واضحة تجعل الموقع يبدو «قديماً» بغضّ النظر عن جودة الكود.

**المشكلة الثانية — وهي الأخطر في تطبيق مالي: تضارب الأخضر.**
التركوازي `#16a085` (لون الهوية) قريب بصرياً من الأخضر `#2ecc71` (دلالة الربح). في تطبيق تداول، الأخضر والأحمر **يجب أن يكونا محجوزين حصرياً لاتجاه السعر**. حالياً العين ترى «أخضر» في كل مكان: كل حدود اللوحات، كل العناوين، شريط التمرير، التبويب النشط — فيفقد الأخضر معناه الإشاري.

**المشكلة الثالثة: الارتفاع (Elevation) معكوس.**
```
خلفية الصفحة   #1a1a2e  (تدرّج إلى #16213e)
اللوحة .panel   #0f3460  ← أزرق مشبع
العنصر داخلها  #1a1a2e  ← عاد إلى لون الصفحة نفسه!
```
التباين بين اللوحة ومحتواها **1.36:1** فقط. في التصميم الداكن، كلما تقدّم العنصر للأمام وجب أن يفتحّ لونه. هنا يعود العنصر الداخلي إلى لون الخلفية، فتُقرأ البطاقات كـ«حُفَر» لا كبطاقات مرتفعة. ولأن الفصل اللوني معدوم، عُوِّض عنه بـ **حدود تركوازية 2px حول كل شيء** — وهذا سبب الإحساس بأن الصفحة «صناديق فوق صناديق».

**المشكلة الرابعة: التوكنات معرّفة ولا تُستخدم.**
`:root` يحوي 18 متغيراً، لكن الملف يستخدم `var()` **21 مرة فقط** مقابل **123 لوناً مباشراً**. أي أن نظام التوكنات موجود شكلياً وغير مفعّل — تغيير لون الهوية اليوم يتطلب بحثاً واستبدالاً في 25 موضعاً.

### 3.2 النظام اللوني المقترح

المبدأ: **لون هوية واحد + رمادي مزرقّ متدرّج + أخضر/أحمر محجوزان للسعر فقط.**

| `--surface-2` | `#18253C` | العناصر داخل اللوحات (مرتفعة للأمام) |
| `--surface-3` | `#22314D` | حالة hover / محدد |
| `--border` | `#24344D` | حدود خفيفة 1px بدل 2px تركوازي |

**كل قيمة في الجدول أعلاه محسوبة، وكلها تتجاوز عتبة AA (4.5) للنص العادي.**

#### ثلاثة قرارات لونية مهمة

1. **إلغاء البنفسجي `#9b59b6` نهائياً.** استخدامه الوحيد (السيناريوهات التاريخية) يمكن أن يعتمد `--warning` أو `--brand`. لون سادس بلا وظيفة دلالية = ضوضاء.
2. **إزالة تدرّج الخلفية `linear-gradient(135deg, ...)`.** التدرّجات القُطرية على كامل الصفحة سمة تصميم 2015. لون صلب واحد أنظف وأسرع في الرسم.
3. **لا تعتمد على اللون وحده للربح/الخسارة.** أضف رمز اتجاه (▲ / ▼) بجانب النسبة — يخدم ~5% من الذكور المصابين بعمى الألوان، ويحسّن سرعة القراءة للجميع.

### 3.3 هل نبقى داكنين؟

الوضع الداكن مناسب لتطبيقات التداول. لكن الملف يحوي `@media (max-width: 768px)` و`prefers-reduced-motion` فقط — **لا يوجد `prefers-color-scheme`**. بما أن نظام التوكنات سيُبنى على أي حال، إضافة وضع فاتح لاحقاً تصبح مسألة كتلة `:root` ثانية فقط. أنصح بتأجيلها إلى مرحلة لاحقة وعدم إدخالها الآن.

## 4. التخطيط والتصميم البصري

### 4.1 لا يوجد رأس (Header) للتطبيق

الصفحة تبدأ مباشرة بشريطين متحركين. لا اسم، لا شعار، لا نقطة تثبيت بصرية. المستخدم الذي يفتح الرابط لا يعرف أين هو.

**المقترح:** شريط علوي بارتفاع 56px يحوي:
- الشعار + اسم «تداول» (يمين في RTL)
- زر تبديل اللغة (بدل الزر العائم الحالي)
- ملخص مصغّر للحالة (السوق مفتوح/مغلق) — يستبدل جزءاً من `.market-status-bar`

### 4.2 الديسكتوب يهدر ~60% من العرض

`.main-content { grid-template-columns: 1fr 1fr }` معرّفة لكن غير مستخدمة. النتيجة على 1440px: قائمة الأسهم بعرض 1360px لعرض اسم سهم وسعر — ثم النصائح تحتها، ثم التحديات تحتها، بتمرير طويل جداً.

**المقترح لشاشات ≥1024px:**
```
┌────────────────────┬─────────────────┐
│ قائمة الأسهم       │ الشارت + نموذج  │
│ (بحث + فرز)        │ الأمر (لوحة     │
│                    │ جانبية ثابتة)   │
├────────────────────┼─────────────────┤
│ المحفظة / الأوامر  │ التحديات        │
└────────────────────┴─────────────────┘
```
الفائدة الكبرى: **الشارت ونموذج الأمر يصبحان جنباً إلى جنب مع القائمة بدل نافذة منبثقة**، وهو النمط القياسي في كل منصات التداول.

### 4.3 «صناديق داخل صناديق»

كل `.panel` له حد تركوازي 2px، وداخله بطاقات لها حدود جانبية 4px بألوان مختلفة (تركوازي للنصائح، برتقالي للتحديات، بنفسجي للسيناريوهات). النتيجة تشتّت بصري: العين لا تعرف أي حدّ مهم.

**المقترح:** الاعتماد على **فرق الأسطح** بدل الحدود:
- اللوحة: `--surface-1` + حد 1px `--border` + `border-radius: 12px`
- البطاقة داخلها: `--surface-2` بلا حدّ إطلاقاً
- الحدود الملوّنة الجانبية 4px: تُستبقى **فقط** حيث تحمل معنى (تحدٍّ نشط، سيناريو مُفعّل)

### 4.4 قائمة 91 سهماً بلا بحث ولا فرز

`.stock-list { max-height: 400px; overflow-y: auto }` — 91 سهماً داخل صندوق تمرير ارتفاعه 400px، **داخل صفحة تُمرَّر أيضاً**. التمرير المتداخل من أسوأ الأنماط على اللمس (المستخدم يمرر الصفحة فتتحرك القائمة أو العكس).

الأخطر: **ملف `src/data/stocks.js` يحتوي حقل `sector` لكل سهم — وهو غير مستخدم في الواجهة إطلاقاً.** الفلتر الوحيد المتاح هو «شرعي/غير شرعي».

**المقترح:**
1. حقل بحث فوري بالاسم أو الرمز (أعلى القائمة، لاصق)
2. شرائح فلترة بالقطاع (بيانات موجودة أصلاً، تحتاج واجهة فقط)
3. فرز: الأكثر ارتفاعاً / انخفاضاً / أبجدياً
4. إلغاء `max-height` على الجوال — دع الصفحة نفسها تُمرَّر (تمرير واحد فقط)

## 5. تجربة الجوال

### 5.1 ميزانية الشاشة

على شاشة 360×740 (شاشة شائعة جداً في السعودية):

| المنطقة | الارتفاع | النسبة |
|---------|----------|--------|
| شريط الأسعار المتحرك | 36px | 4.9% |
| شريط الأخبار المتحرك | 36px | 4.9% |
| فجوة مكسورة | 32px | 4.3% |
| شريط الإحصائيات اللاصق | 122px | 16.5% |
| **الإجمالي المحجوز** | **226px** | **30.5%** |

**قبل أن يرى المستخدم سهماً واحداً، ثلث الشاشة مُستهلك.**

**المقترح:**
- **دمج الشريطين المتحركين في شريط واحد** يتناوب بين الأسعار والأخبار (توفير 36px). الشريطان المتحركان في اتجاهين متعاكسين فوق بعضهما مصدر إجهاد بصري بحد ذاته.
- **تقليص الإحصائيات اللاصقة إلى سطر واحد** يعرض «إجمالي الأصول + الربح/الخسارة» فقط (~44px)، مع بقية الأرقام في البطاقات غير اللاصقة. توفير ~78px.
- الحصيلة: من 226px إلى ~80px، أي **استرجاع 20% من الشاشة**.

### 5.2 لا شريط تنقّل سفلي

التبويبات (السوق / المحفظة / الأوامر) في أعلى الصفحة، وشريط الإجراءات (5 أزرار: قاموس، إحصائيات، تعلم، سيناريوهات، جولة) ينكسر على **3 صفوف** على 360px.

**المقترح لنمط الجوال:** شريط تنقّل سفلي (bottom tab bar) بأربعة عناصر — السوق، المحفظة، الأوامر، المزيد — مع نقل الأزرار الخمسة إلى ورقة سفلية (bottom sheet) تحت «المزيد». هذا هو الموضع الطبيعي لإبهام المستخدم، ويحرر أعلى الشاشة بالكامل.

### 5.3 نقطة توقف واحدة فقط

الملف كله يحوي `@media (max-width: 768px)` واحدة. لا شيء بين 768px و1400px، فتظهر الأجهزة اللوحية (768–1024) بنسخة الديسكتوب المضغوطة. المقترح: 3 نقاط — 640 / 1024 / 1400.

### 5.4 تفاصيل جوال مفقودة

| العنصر | الحالة | المقترح |
|--------|--------|---------|
| `100vh` | مستخدم في `body` | استخدام `100dvh` — `100vh` يسبب قفزة عند ظهور/اختفاء شريط عنوان المتصفح |
| `env(safe-area-inset-*)` | غير مستخدم | مطلوب لأجهزة iPhone ذات النتوء/شريط الإيماءات |
| `--stat-label` على الجوال | **10px** | لا يقل عن 12px |
| أرقام الأسعار | `tabular-nums` على الشريط المتحرك فقط | تطبيقها على كل الأسعار — الأرقام حالياً «ترقص» عند كل تحديث |
| `theme-color` meta | غير موجود | يلوّن شريط المتصفح على الجوال |
| Web App Manifest | غير موجود | يتيح «إضافة إلى الشاشة الرئيسية» — مناسب جداً لمحاكي يُستخدم بشكل متكرر |

## 6. الطباعة والخط العربي

```css
font-family: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif;
```

هذه المشكلة الأكبر التي لا يلاحظها أحد صراحةً لكنها تُشعر الموقع بأنه «غير احترافي»:

1. **`Segoe UI` و`Verdana` لا تحويان محارف عربية جيدة** — على أندرويد و iOS يسقط المتصفح إلى الخط النظامي، فيختلف شكل الموقع اختلافاً جذرياً بين ويندوز والجوال.
2. **`Tahoma`** هو الخط العربي الفعلي على ويندوز، وهو خط واجهة نظام من التسعينات — أحد أوضح أسباب الإحساس بـ«القِدَم».
3. **لا يوجد `line-height` على `body` إطلاقاً.** النص العربي يحتاج ارتفاع سطر أكبر من اللاتيني (1.7 تقريباً) بسبب التشكيل والنقاط والحروف النازلة.

**المقترح:**
```css
:root { --font-ar: 'IBM Plex Sans Arabic', 'Noto Sans Arabic', system-ui, sans-serif; }
body { font-family: var(--font-ar); line-height: 1.7; }
```
`IBM Plex Sans Arabic` و`Noto Sans Arabic` مجانيان (SIL OFL)، ومصمَّمان للواجهات لا للمطبوعات، ويدعمان الأوزان المتغيرة. **ملاحظة مهمة:** سياسة الأمان الحالية `font-src 'self'` تمنع الخطوط الخارجية — لذا يجب تحميل الخط محلياً داخل المشروع (وهذا الأفضل للأداء أيضاً، ولا يتطلب تعديل CSP).

للأرقام: استخدام `font-variant-numeric: tabular-nums` عالمياً على كل قيمة مالية.

## 7. إمكانية الوصول (ما تم إنجازه وما ينقص)

**نقاط قوة حقيقية في الكود الحالي** — تستحق التنويه:
- `prefers-reduced-motion` مطبّق بشكل صحيح ويوقف الشريطين المتحركين
- الشريطان `aria-hidden` مع منطقة `aria-live` بديلة للأخبار
- `role="tablist"` / `role="dialog"` / `role="progressbar"` مستخدمة بشكل سليم
- `inset-inline-start/end` بدل `left/right` — دعم RTL/LTR صحيح
- تعليقات داخل CSS تشرح قرارات تباين سابقة

**ما ينقص:**

| البند | الحالة |
|-------|--------|
| تباين التبويب النشط والتحذير الأحمر | ❌ فشل (§2.5) |
| أهداف لمس خانات الاختيار | ❌ 13×13px (§2.4) |
| الاعتماد على اللون وحده للربح/الخسارة | ❌ لا رموز اتجاه |
| `:focus-visible` | ✅ موجود (`#f1c40f` بسماكة 3px) لكن يجب توحيده مع `--brand` |
| `prefers-contrast: more` | ❌ غير مدعوم |
| حجم الخط الأدنى | ⚠️ 10px في `.stat-label` على الجوال |
