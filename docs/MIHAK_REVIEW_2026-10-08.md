المشروع محاكي تداول تعليمي لسوق تداول (Tadawul). فيه 91 سهمًا بأسعار تولّدها حركة براونية هندسية (GBM)، وأوامر سوق ومحددة ووقف خسارة، وأخبار تحرّك الأسعار، وسيناريوهات ودروس ومسرد، وواجهة ثنائية اللغة عربي/إنجليزي. يشتغل كله في المتصفح بلا خادم، والحالة محفوظة في `localStorage`.

## 2. المراجعة التقنية والهندسية (45%)

### 2.1 البنية المعمارية وفصل المسؤوليات: **9/10**

الفصل ممتاز وثابت. `engine/trading.js` ما يلمس الـ DOM أبدًا، ويرجّع نتائج مثل `{ ok, error }` يترجمها `main.js` في `errorMessageFor()`. ومنح مكافآت التحديات طلع من الرسّام إلى `engine/challenges.js`، والتعليق في `refreshAll()` يشرح السبب صح ("a repaint should never do that").

الملاحظة الوحيدة إن `engine/prices.js` و`engine/trading.js` يقرون ويكتبون الحالة العامة المشتركة (`gameState` و`stockPrices`) مباشرة بدل ما تنمرّر لهم. هذا مقبول لمشروع بهالحجم، لكنه يخلّي الاختبارات تعتمد على حالة عامة تنصفّر بين الاختبارات. ما يستاهل تغيير الحين.

### 2.2 قابلية القراءة والصيانة: **8/10**

الدوال قصيرة والتسمية واضحة. لكن فيه نمط صار يتكرر: **تعليقات تحكي تاريخ الباقات بدل ما تشرح الكود الحالي**. أمثلة:

> `src/ui/dom.js`، في التعليق فوق `html()`:
> ```js
> * The previous convention was to call escapeHtml() by hand at each `${}`, with
> * an ESLint rule meant to catch a forgotten one. That rule matched only a
> * variable literally named `element`, so it flagged none of the real sinks...
> ```

> `src/engine/prices.js`، داخل `gbmStep()`: تعليق من 12 سطرًا عن `ticksLeft` يحكي محاكاة قديمة طلّعت "single-tick drifts past 13,000%".

القارئ الجديد يحتاج يعرف **ليش** الكود كذا، مو وش كان الخطأ القديم. مكان هالقصة رسالة الـ commit. الحل: اختصر هالتعليقات لسطر أو سطرين عن القيد الحالي. مثلًا:

```js
// Clamp to >=1: the divisor is "ticks left", and a re-phased interval can land
// a tick just before expiry, which would apply the remaining impact at once.
const ticksLeft = Math.max(1, news.duration - elapsed);
```

### 2.3 التكرار (DRY) و Code Smells: **8/10**

التكرار القديم انحلّ: `clearChildren` و`direction()` و`html```. اللي باقي:

- **`src/ui/stock-details.js` و`src/ui/render.js`**: نفس سطر تنسيق السعر مكرر:
  ```js
  priceText: `${price.toFixed(2)} ${t('sar')}`,          // stock-details.js — priceFieldsFor()
  refs.priceEl.textContent = `${price.toFixed(2)} ${t('sar')}`; // render.js — updateStockPrices()
  ```

  ونفس الشي لنص التغيّر `${glyph} ${Math.abs(change).toFixed(2)}%`. الحل: دالة `formatPrice(price)` و`formatChange(change)` في `utils/numbers.js` جنب `formatCurrency`.
- **`src/engine/trading.js`**: الحد `{ min: 0.01, max: 100000 }` مكتوب مرتين داخل `validateOrder()` بدل ثابت في `config.js` مثل `MAX_ORDER_QUANTITY`.

### 2.4 معالجة الأخطاء والحالات الحدّية: **8/10**

التحقق من الحفظ المحمّل (`sanitizeLoadedState` و`sanitizeLoadedStats`) قوي، وكل وصول لـ `localStorage` ملفوف بـ `try/catch`. الثغرات الباقية:

1. **`src/engine/trading.js`، في `executeMarketOrder()`**: الفحص المسبق `canFill()` يحسب على السعر الفوري، والتنفيذ يصير على السعر بعد الانزلاق والأثر:
   ```js
   const preCheck = canFill(order);
   if (!preCheck.ok) return preCheck;
   const price = applyMarketImpact(order.symbol, order.type, order.quantity); // يحرّك السوق
   const result = order.type === 'buy' ? applyBuy(...) : applySell(...);
   if (!result.ok) return result; // ← السعر انحرك ورجع خطأ، وما فيه rollback
   ```
   التعليق يعترف بالحالة ويعتبرها نادرة، لكنه يناقض هدف الدالة المكتوب نفسه ("a rejected order leaves no trace"). المستخدم اللي يحاول يشتري بكل رصيده يقدر يحرّك السعر مرة بعد مرة بأوامر مرفوضة. الحل الأرخص: احسب السعر النهائي بدالة نقية `previewImpact()` بدون كتابة، وتحقق منه، وبعدين طبّقه.
2. **`src/state.js`، في `sanitizeLoadedState()`**: فلتر المعاملات يتحقق من `symbol` و`price` و`quantity` بس:
   ```js
   (tx) => tx && typeof tx.symbol === 'string' && Number.isFinite(tx.price) && Number.isFinite(tx.quantity)
   ```
   `tx.time` و`tx.type` ما يتحقق منها، فحفظ تالف فيه `time` غير رقمي يخلّي `new Date(tx.time).toISOString()` في `buildTransactionsCsv()` **يرمي `RangeError`** ويكسر التصدير كله. الحل: أضف `Number.isFinite(tx.time) && (tx.type === 'buy' || tx.type === 'sell')`.
3. **`src/state.js`**: `activeScenario.id` يُقبل كأي نص، بدون ما يتأكد إنه موجود في `data/scenarios.js`. لو تغيّر اسم سيناريو، يتحمّل سيناريو "شبح". الحل: تحقق منه عبر دالة بحث مثل `findStock`.

### 2.5 الأداء واستهلاك الموارد: **7/10** (كان 6)

## 3. المظهر والتصميم وتجربة المستخدم (30%)

### 3.1 الاتساق البصري: **9/10**

كل الألوان من متغيرات CSS (`--brand` و`--gain` و`--loss` و`--text-2`...)، ويغطيها وضع فاتح وداكن وتباين عالٍ (`prefers-contrast: more`)، والرسوم تقرأ نفس المتغيرات عبر `themeColor()`. الاستثناء الوحيد إن `src/ui/candlestick.js` يرسم النصوص بـ `ctx.font = '11px sans-serif'` بدل IBM Plex، فأرقام محور الشموع تطلع بخط غير خط باقي الواجهة. الحل: اقرأ `getComputedStyle(document.body).fontFamily`.

### 3.2 سهولة الاستخدام والتنقل: **7/10**

المهمة الأساسية سريعة (اختيار السهم ثم الكمية ثم شراء)، والبحث والفلترة موجودة. لكن فيه ثلاث مشاكل تكسر الثقة:

1. **ترتيب "الأعلى ارتفاعًا/انخفاضًا" يصير قديم بصمت.** `selectStocks()` يرتّب مرة وحدة بس، داخل `renderStocks()`، و`refreshAll()` ينادي `updateStockPrices()` اللي يحدّث النصوص بدون ما يعيد الترتيب. بعد كم نبضة، القائمة المعنونة "الأعلى ارتفاعًا" تعرض أسهم نازلة فوق أسهم طالعة. الحل: لما يكون `listFilters.sort` واحد من `gainers` أو `losers`، أعد الترتيب كل نبضة بنقل العقد الموجودة (`appendChild` لنفس العنصر يحرّكه بدون ما يبنيه من جديد)، أو أضف زر "تحديث الترتيب" ظاهر.
2. **نوع الأمر يرجع "سوق" بصمت.** `renderStockDetails()` يبني نموذج الأمر من جديد مع تبديل اللغة أو السمة أو عبور حد 1024px. المؤشرات صارت تنحفظ (`indicatorState`)، لكن نوع الأمر وسعر الحد ما ينحفظون:
   ```html
   <input type="radio" name="orderType" value="market" checked />
   ```
   مستخدم كان مجهّز أمر وقف خسارة ودوّر الجوال، يضغط "بيع" فيتنفذ **أمر سوق فوري**. هذا أخطر من مجرد إزعاج، لأن النتيجة صفقة ما قصدها المستخدم. الحل: احفظ `orderKind` وقيمة `order-price` في كائن مثل `indicatorState` وأرجعها بعد البناء.
3. **أمر بيع محدد بدون أسهم مقبول.** `validateOrder()` يتحقق من الملكية لأمر وقف الخسارة بس، فأمر "بيع محدد" لسهم ما تملكه ينقبل بـ toast «تمت إضافة الأمر»، وبعدين ينلغي تلقائيًا لما يتحقق شرطه. الحل: طبّق فحص `NO_HOLDING` على `type === 'sell'` لكل الأنواع المعلّقة.

### 3.3 الاستجابة: **9/10**

نقاط توقف عند 640 و767 و1024 و1400px، ومتغير `--tap-min: 44px` مطبّق على الأزرار والمفاتيح، و`100dvh`، وشريط تنقل سفلي على الجوال. ما لقيت مشكلة في الكود. أما الحكم على الإحساس الفعلي على أجهزة حقيقية فهذا **لا يمكن تقييمه من الكود وحده**.

### 3.4 العربية و RTL: **8/10**

- `<html lang="ar" dir="rtl">`، و`rebuildStaticLabels()` يقلب `dir` و`lang` على `documentElement` مع تبديل اللغة. ✅
- الـ CSS ما فيه `margin-left` أو `padding-right` ثابتة (فحصت الملف كامل)، يعني الخصائص المنطقية مستخدمة. ✅
- الأرقام موحّدة لاتينية عبر `ar-SA-u-nu-latn` في `formatCurrency()`. هذا قرار مقصود وموثّق. ✅
- الخط عربي مستضاف ذاتيًا، بثلاثة أوزان فقط. ✅
- ⚠️ **الإدخال بالأرقام الهندية (١٢٣) غير معالج.** `safeParseNumber()` في `utils/numbers.js` يسوي `Number(raw)`، و`Number('١٠٠')` يرجّع `NaN`. وعلى `<input type="number">` المتصفحات تختلف: بعضها يرفض المحارف ويرجّع `value = ''`، وبعضها يحوّلها. سلوك لوحات المفاتيح العربية الفعلي على أندرويد وiOS **يحتاج تجربة فعلية**. لكن الكود ما فيه أي تطبيع، فأفضل حالة إن المستخدم يشوف «أدخل كمية صحيحة» وهو مدخل كمية صحيحة. الحل: طبّع الأرقام قبل التحليل، و`type="text" inputmode="numeric"` يضمن إن القيمة توصل للكود كما كتبها المستخدم:
  ```js
  const normalized = String(raw).replace(/[٠-٩]/g, (d) => d.charCodeAt(0) - 0x0660)
                                .replace(/[۰-۹]/g, (d) => d.charCodeAt(0) - 0x06f0)
                                .replace('٫', '.');
  ```
- 🟡 الشموع ترسم محور الأسعار على اليسار دائمًا (`padding.left`، `textAlign = 'right'`) بغض النظر عن الاتجاه. هذا مقبول لأن الرسوم المالية تُقرأ زمنيًا من اليسار لليمين حتى في الواجهات العربية.

### 3.5 إمكانية الوصول: **7/10** (كان 8)

الأساسيات قوية: `inert` على الخلفية مع فخ تركيز في المودال، و`aria-live` للأخبار، والاتجاه يُعرض بسهم مو بلون فقط. لكن:

1. **التركيز يضيع كل نبضة.** `renderPortfolio()` و`renderPendingOrders()` يسوون `clearChildren()` ويبنون الأزرار من جديد كل نبضة:
   ```js
   clearChildren(portfolioEl);
   ...
   sellBtn.addEventListener('click', () => onQuickTrade(symbol, 'sell'));
   ```
   مستخدم لوحة المفاتيح أو قارئ الشاشة اللي وصل بالـ Tab لزر «بيع الكل» أو «إلغاء الأمر» يطيح تركيزه على `<body>` مع أول نبضة (كل 6 ثوانٍ على 10x). وحتى بالماوس، ضغطة تبدأ قبل النبضة وتنتهي بعدها تضيع لأن الزر انحذف. **هذي أخطر ملاحظة UX في المراجعة.** الحل: نفس نمط `stockItemRefs` المطبّق على قائمة الأسهم. احتفظ بخريطة `symbol → refs`، وحدّث النصوص بس، وابنِ أو احذف العنصر لما يدخل أو يطلع رمز. أو على الأقل احفظ `document.activeElement` بمعرّف ثابت (`data-action` + `data-symbol`) وأرجعه بعد البناء.
2. **تسمية مجموعة نوع الأمر غلط.** في `src/ui/stock-details.js`:
   ```html
   <div class="order-type" role="radiogroup" aria-label="${t('orderKindLimit')}">
   ```
   قارئ الشاشة يعلن المجموعة كلها باسم «أمر محدد»، وهي تحتوي سوق ومحدد ووقف خسارة. الحل: مفتاح ترجمة جديد `orderTypeGroup` («نوع الأمر» / «Order type»).
3. **الرسم بلا بديل نصي.** `<canvas aria-label="${t('currentPrice')}">` يقول «السعر الحالي» بس، بدون الرقم ولا الاتجاه. الحل: `aria-label` ديناميكي يُحدَّث في `patchStockDetails()`، مثل «السعر 32.45 ريال، ▲ 1.2% خلال آخر 100 نقطة».
